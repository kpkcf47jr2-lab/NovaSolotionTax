📊 API ENDPOINTS SUMMARY

1. POST /api/tickets (900 lines)
   ├─ Input: title, description, category, priority, returnId?, source?
   ├─ Process: Validate → Calculate SLA → Create → Queue monitor
   ├─ Output: New ticket with SLA dates
   ├─ Rate limit: 10/min
   ├─ Auth: Required
   └─ Cost: Free (internal endpoint)

2. GET /api/tickets (200 lines)
   ├─ Query: status?, priority?, assignedToMe?, search?, page?, limit?
   ├─ Returns: Paginated list (20 per page default)
   ├─ Filters: Access control by role
   ├─ Sorting: Priority DESC, Created DESC
   └─ Rate limit: Unlimited

3. GET /api/tickets/:ticketId (250 lines)
   ├─ Returns: Full ticket with comments + attachments
   ├─ Includes: SLA status, escalation history
   ├─ Access: Creator, assignee, or support/admin
   └─ Performance: Single query with includes

4. PATCH /api/tickets/:ticketId (180 lines)
   ├─ Updates: title, description, priority, status, assignedToId
   ├─ Permissions: Assignee or support/admin only
   ├─ Actions: Update timestamp, create audit, trigger workflows
   ├─ Resolved: Auto-queue follow-up survey
   └─ Rate limit: Unlimited

5. POST /api/tickets/:ticketId/comments (220 lines)
   ├─ Input: content, isInternal?, attachmentIds?
   ├─ Internal comments: Support staff only
   ├─ Notifications: Sent to creator on public comments
   ├─ Attachments: Linked to comment
   ├─ Rate limit: 30/min
   └─ Audit: All comments logged

6. GET /api/tickets/stats/dashboard (180 lines)
   ├─ Returns: Ticket counts by status/priority
   ├─ Metrics: Avg resolution time, SLA breaches
   ├─ Access: Support staff and admin only
   ├─ Performance: Aggregated queries
   └─ Real-time: Calculated on demand
