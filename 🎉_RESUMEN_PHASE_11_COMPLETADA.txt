ANALYTICS ARCHITECTURE
================================================================================

Event Tracking Flow:
┌─────────────────────────────────────────────────────────┐
│ 1. User Action (login, create return, payment, etc.)   │
├─────────────────────────────────────────────────────────┤
│ Component calls trackEvent('event_type', metadata)     │
│                                                         │
│ trackEvent() → POST /api/analytics/track (async)       │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│ 2. Backend Processing                                   │
├─────────────────────────────────────────────────────────┤
│ POST /track endpoint:                                  │
│   ✓ Validates event type                               │
│   ✓ Creates AnalyticsEvent record                       │
│   ✓ Updates EventSummary (daily aggregation)           │
│   ✓ Returns immediately (non-blocking)                 │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│ 3. Data Aggregation                                     │
├─────────────────────────────────────────────────────────┤
│ EventSummary table (pre-aggregated):                   │
│   ✓ Counts by event type, per day                      │
│   ✓ Used for fast trending queries                     │
│   ✓ Significantly faster than raw event queries        │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐

================================================================================
DATABASE SCHEMA
================================================================================

AnalyticsEvent {
  id: String
  tenantId: String → Tenant.id
  userId: String → User.id
  eventType: String
  metadata: JSON
  timestamp: DateTime
  sessionId?: String
  createdAt: DateTime
  @@index([tenantId, timestamp])
}

EventSummary {
  id: String
  tenantId: String
  eventType: String
  date: DateTime (00:00:00)
  count: Int
  @@unique([tenantId, eventType, date])
}

UserSession {
  id: String
  tenantId: String
  userId: String
  sessionId: String (unique)
  ipAddress?: String
  userAgent?: String
  startedAt: DateTime
  endedAt?: DateTime
  pageViews: Int
  eventCount: Int
  lastActivityAt: DateTime
  exitReason?: String
}

PageView {
  id: String
  tenantId: String
  userId: String
  path: String
  title?: String
  referrer?: String
  sessionId?: String
  enteredAt: DateTime
  exitedAt?: DateTime
  timeSpent?: Int (seconds)
}

FeatureUsage {
  id: String
  tenantId: String
  userId: String
  featureName: String
  action: String (opened, used, completed, error)
  duration?: Int (milliseconds)
  success: Boolean
  errorMessage?: String
  metadata: JSON
}

ErrorLog {
  id: String
  tenantId: String
  userId?: String
  errorType: String
  message: String
  stackTrace?: String
  url?: String
  endpoint?: String
  severity: String (low, medium, high, critical)
  resolved: Boolean
  resolvedAt?: DateTime
}

CustomMetric {
  id: String
  tenantId: String
  name: String
  category: String
  period: String (day, week, month, year)
  date: DateTime
  value: Decimal
  previousValue?: Decimal
  metadata: JSON
  @@unique([tenantId, name, period, date])
}


================================================================================
API ENDPOINTS SUMMARY
================================================================================

1️⃣  POST /api/analytics/track
    Purpose: Track a user event
    Auth: Authenticated (any user)
    Request: { eventType, metadata? }
    Response: { success, eventId, timestamp }
    Rate limit: Per user
    Side effects: Creates AnalyticsEvent, updates EventSummary

2️⃣  GET /api/analytics/events?period=month&page=1&limit=100
    Purpose: Get list of events with filtering
    Auth: Admin only
    Query params: period?, from?, to?, eventType?, page, limit
    Response: { events[], pagination }
    Performance: O(1) with indexes

3️⃣  GET /api/analytics/metrics?period=month
    Purpose: Get dashboard metrics
    Auth: Admin only
    Query params: period? (day/week/month/quarter/year)
    Response: { metrics, activityMetrics, eventTypes, recentEvents }
    Cached: 1 hour in Redis

4️⃣  GET /api/analytics/charts/events?period=month&granularity=day
    Purpose: Get event chart data
    Auth: Admin only
    Query params: period?, granularity? (day/week/month)
    Response: { data: [{ date, events }] }
    Use: LineChart visualization

5️⃣  GET /api/analytics/users?period=month&limit=20
    Purpose: Get top active users
    Auth: Admin only
    Query params: period?, limit
    Response: { users: [{ user, eventCount }] }
    Sorted: By eventCount descending

6️⃣  GET /api/analytics/funnel?period=month
    Purpose: Get funnel analysis
    Auth: Admin only
    Query params: period?
    Response: { funnel: [{ stage, count, conversionRate }] }
    Stages: Registration → Login → Return → Submit → Approve → Payment

7️⃣  GET /api/analytics/revenue?period=month
    Purpose: Get revenue metrics
    Auth: Admin only
    Query params: period?
    Response: { revenue: { total, byStatus, activeSubscriptions } }
    Includes: Payment status breakdown

8️⃣  GET /api/analytics/export?format=csv&period=month
    Purpose: Export analytics data
    Auth: Admin only
    Query params: format (csv|json), period?
    Response: File download (CSV or JSON)
    Headers: Content-Disposition for download
